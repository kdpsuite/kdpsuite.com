# Deployment Operations Checklist

Operational steps for deploying kdpsuite.com to production. Code deploys via Vercel; database and third-party services require manual setup.

## 1. Supabase Migrations

Run these SQL files in the Supabase SQL editor (production project), in order:

1. `SUPABASE_USER_PROFILES_SETUP.sql` — user profiles + RLS
2. `WAITLIST_SIGNUPS_SETUP.sql` — waitlist table
3. `WEBINAR_REGISTRATIONS_SETUP.sql` — webinar signup persistence
4. `REFERRALS_SETUP.sql` — referral program tracking
5. `PROCESSED_STRIPE_EVENTS_SETUP.sql` — Stripe webhook idempotency
6. `RLS_HOTFIX.sql` — billing field protection hotfix

Verify in Supabase Dashboard → Table Editor that all tables exist with RLS enabled.

## 2. RLS Hotfix

After running `RLS_HOTFIX.sql`, confirm authenticated users can only update safe profile columns (`full_name`, `username`, `avatar_url`, `bio`) and cannot self-escalate billing fields.

## 3. Vercel Environment Variables

Set in Vercel → Project → Settings → Environment Variables (Production + Preview):

| Variable | Required | Notes |
|----------|----------|-------|
| `NEXT_PUBLIC_SUPABASE_URL` | Yes | Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Yes | Public anon key |
| `SUPABASE_SERVICE_ROLE_KEY` | Yes | Server-only; never expose client-side |
| `NEXT_PUBLIC_APP_URL` | Yes | `https://kdpsuite.com` |
| `STRIPE_SECRET_KEY` | Yes | Stripe live/test secret |
| `STRIPE_WEBHOOK_SECRET` | Yes | From Stripe webhook endpoint |
| `STRIPE_ALLOWED_PRICE_IDS` | Yes | Comma-separated price IDs |
| `NEWSLETTER_PROVIDER` | For newsletter | `mailchimp` or `brevo` |
| `MAILCHIMP_API_KEY` + `MAILCHIMP_LIST_ID` | If Mailchimp | ESP credentials |
| `BREVO_API_KEY` + `BREVO_LIST_ID` | If Brevo | ESP credentials |
| `EMAIL_USER` + `EMAIL_PASSWORD` | For contact form | SMTP credentials |
| `ADMIN_API_SECRET` | For admin APIs | Waitlist stats endpoint |
| `SENTRY_DSN` | Optional | Error tracking stub |

See `.env.example` for the full list.

## 4. Stripe Webhook

1. Create webhook endpoint: `https://kdpsuite.com/api/stripe/webhook`
2. Events: `customer.subscription.*`, `invoice.payment_succeeded`, `invoice.payment_failed`
3. Copy signing secret to `STRIPE_WEBHOOK_SECRET`
4. Ensure `processed_stripe_events` table exists before first webhook delivery

## 5. Supabase Auth URLs

In Supabase → Authentication → URL Configuration:

- Site URL: `https://kdpsuite.com`
- Redirect URLs: `https://kdpsuite.com/auth/login`, `https://kdpsuite.com/auth/reset-password`

## 6. Search Console & Bing

### Google Search Console

1. Verify domain (file at `/public/a893d08d1c9d4429b266d5faaf5f41ff.txt`)
2. Submit sitemap: `https://kdpsuite.com/sitemap.xml` (generated by `app/sitemap.ts`)
3. Confirm robots: `https://kdpsuite.com/robots.txt` (generated by `app/robots.ts`)

### Bing Webmaster Tools

1. Verify site (file at `/public/BingSiteAuth.xml`)
2. Submit sitemap: `https://kdpsuite.com/sitemap.xml`

## 7. Post-Deploy Smoke Tests

- [ ] Homepage loads with security headers (CSP, HSTS)
- [ ] Waitlist signup works
- [ ] Auth: signup, login, forgot password, reset password
- [ ] Profile edit at `/dashboard/profile`
- [ ] Newsletter subscribe (with ESP configured)
- [ ] Webinar register (persists to Supabase)
- [ ] Referral link `?ref=<user-id>` sets cookie; signup records referral
- [ ] Stripe checkout + webhook (test mode first)
- [ ] Admin waitlist: `GET /api/admin/waitlist` with `Authorization: Bearer <ADMIN_API_SECRET>`

## 8. Admin API Examples

```bash
# Waitlist stats
curl -H "Authorization: Bearer $ADMIN_API_SECRET" \
  https://kdpsuite.com/api/admin/waitlist

# Legacy waitlist count
curl -H "Authorization: Bearer $ADMIN_API_SECRET" \
  "https://kdpsuite.com/api/waitlist?action=count"
```
